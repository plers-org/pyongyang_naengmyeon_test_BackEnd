그림에 나온 말들

AWS VPC

아마존 땅 안에 담장을 두른 우리 전용 부지입니다. 담장 안의 기계끼리는 자유롭게 대화하고, 바깥에서는 우리가 열어준 문으로만 들어올 수 있습니다. Virtual Private Cloud · 가상 사설 클라우드

EC2

그 부지에 세운 컴퓨터 한 대입니다. 내 맥과 똑같이 프로그램을 설치하고 켜고 끌 수 있는데, 아마존 데이터센터에 있어서 24시간 돌아갑니다. 여기에 우리 파이썬 코드가 올라갑니다

t3.micro

그 컴퓨터의 크기 등급입니다. CPU 2개에 메모리 1GB로 가장 작은 축이고, 프리티어 무료 대상입니다. 나중에 사용자가 늘면 더 큰 등급으로 바꿀 수 있습니다.

nginx

건물 정문의 안내 데스크입니다. 인터넷에서 오는 손님을 전부 여기서 받아 안쪽 담당자에게 넘깁니다. 우리 앱이 인터넷에 직접 노출되지 않게 막아주는 역할이라 실무에서 거의 항상 씁니다. 읽는 법: 엔진엑스

FastAPI

우리가 이미 짜둔 파이썬 코드 자체입니다. 설문 문항을 내려주고 응답을 받아 추천 결과를 계산하는 부분이 여기에 해당합니다.

uvicorn

그 파이썬 코드를 실행해서 요청에 답하게 해주는 실행기입니다. 코드만 있으면 스스로 손님을 받을 수 없어서, uvicorn이 코드를 띄우고 대기시킵니다. 읽는 법: 유비콘

포트 · :80 :8000 :5432

건물의 출입구 번호입니다. 컴퓨터 한 대에 출입구가 여러 개 있고, 프로그램마다 자기 번호를 씁니다. 80은 웹의 기본 출입구, 5432는 PostgreSQL 전용 출입구입니다.

127.0.0.1:8000

127.0.0.1은 이 컴퓨터 자기 자신을 뜻하는 주소입니다. 즉 8000번은 건물 내선 번호라서 바깥에서는 걸 수 없고, 같은 건물 안의 nginx만 연결할 수 있습니다. 앱을 일부러 안쪽에 숨겨둔 것입니다.

RDS

아마존이 대신 관리해주는 데이터베이스 서버입니다. 우리가 직접 설치·백업·업데이트를 하지 않아도 알아서 처리해주고, 고장 나면 복구해줍니다. Relational Database Service

db.t4g.micro

그 DB 서버의 크기 등급입니다. t3.micro가 앱 컴퓨터 등급이었듯이, 이건 DB 컴퓨터 등급이고 역시 가장 작은 축이자 프리티어 대상입니다.

PostgreSQL 16

데이터를 표 형태로 쌓아두는 프로그램의 이름과 버전입니다. 식당 정보와 맛 점수가 엑셀 표처럼 여기에 저장되고, 앱이 필요할 때 꺼내 씁니다. 읽는 법: 포스트그레스큐엘, 줄여서 포스트그레스

퍼블릭 접근 차단

DB를 인터넷에 아예 내놓지 않는 설정입니다. 누가 DB 주소와 암호를 알아내도 EC2를 거치지 않으면 닿을 수 없습니다. 그림에서 RDS로 가는 화살표가 담장 안에서만 그려진 이유입니다.

스토리지 20GB

DB가 자료를 담아두는 창고 크기입니다. 설문 응답 데이터라면 아주 오래 써도 남습니다.

시작하기 전에

  • AWS 계정 — 없으면 aws.amazon.com에서 가입합니다. 신용카드 등록이 필요하지만, 아래 구성은 프리티어 범위 안입니다.
  • 맥 터미널 — Spotlight(⌘+Space)에서 "터미널"을 검색해 엽니다.
  • 리전 고정 — AWS 콘솔 오른쪽 위 지역 선택에서 아시아 태평양(서울) ap-northeast-2를 고릅니다. 이후 모든 작업에서 이 리전이 유지되어야 합니다. 리전이 다르면 만들어둔 자원이 목록에 안 보입니다.
먼저 정해둘 것

DB 마스터 암호를 지금 정하고 메모장에 적어두세요. 영문 대소문자와 숫자만 쓰고 12자 이상으로 만듭니다. @ : / # 같은 기호를 넣으면 접속 주소(DATABASE_URL)를 만들 때 주소가 잘못 해석되어 연결이 실패합니다.

예시 형태: NaengmyeonDb2026 — 이 예시를 그대로 쓰지 말고 본인 것으로 바꾸세요.

배포 절차

  1. 1

    보안 그룹 두 개 만들기

    EC2 콘솔 · 약 5분 · 순서 중요

    보안 그룹은 서버의 방화벽입니다. 앱 서버용과 DB 서버용을 따로 만드는데, 앱용을 먼저 만들어야 합니다. DB용이 앱용을 지목하는 방식으로 연결되기 때문입니다.

    EC2 콘솔 → 왼쪽 메뉴 네트워크 및 보안 → 보안 그룹 → 보안 그룹 생성.

    첫 번째 — 앱 서버용

    이름
    plers-app-sg
    설명
    app server
    인바운드 규칙 1
    유형 SSH · 소스 내 IP
    인바운드 규칙 2
    유형 HTTP · 소스 Anywhere-IPv4

    두 번째 — DB 서버용 (앱용을 만든 뒤에 생성)

    이름
    plers-db-sg
    설명
    rds postgres
    인바운드 규칙
    유형 PostgreSQL · 소스 칸에 plers-app-sg를 입력해 목록에서 선택
    왜 이렇게 하나

    DB 소스를 IP가 아니라 앱 보안 그룹으로 지정하면, 그 앱 서버만 DB에 접속할 수 있고 외부 인터넷에서는 아예 닿을 수 없습니다. 비밀번호가 새어나가도 DB가 바로 털리지 않습니다.

    보안 그룹 목록에 plers-app-sg와 plers-db-sg 두 개가 보이면 완료.

    생성에 시간이 걸리니 이 단계를 먼저 시작하고, 기다리는 동안 3단계를 진행하면 됩니다.

    RDS 콘솔 → 데이터베이스 생성 → 표준 생성 선택 (손쉬운 생성 아님).

    엔진
    PostgreSQL
    버전
    기본 제시된 16.x 이상 그대로
    템플릿
    프리 티어 (없으면 개발/테스트 + db.t4g.micro)
    DB 인스턴스 식별자
    plers-db
    마스터 사용자 이름
    plersadmin
    마스터 암호
    위에서 정한 영문+숫자 암호
    인스턴스 클래스
    db.t4g.micro
    스토리지
    gp3 · 20GB · 자동 조정 끄기
    퍼블릭 액세스
    아니요
    VPC 보안 그룹
    기존 항목 선택 → plers-db-sg
    (기본으로 잡힌 default는 반드시 제거)
    추가 구성 →
    초기 데이터베이스 이름
    plers ← 빠뜨리기 쉬움
    자동 백업
    켜두기 (기본 7일)
    가장 흔한 실수

    맨 아래 추가 구성을 펼쳐서 초기 데이터베이스 이름에 plers를 넣어야 합니다. 비워두면 PostgreSQL 서버만 생기고 그 안에 데이터베이스가 만들어지지 않아, 나중에 앱이 접속할 때 database "plers" does not exist 오류가 납니다.

    또한 스토리지 자동 조정을 꺼야 예상치 못한 요금이 안 붙습니다.

    데이터베이스 생성을 누르면 상태가 "생성 중"으로 바뀝니다. 15~20분 걸리니 그대로 두고 3단계로 넘어가세요.

    상태가 사용 가능으로 바뀌면 plers-db를 눌러 엔드포인트 주소를 복사해 메모장에 적어둡니다. plers-db.xxxxx.ap-northeast-2.rds.amazonaws.com 형태입니다.

    EC2 앱 서버 만들기

    EC2 콘솔 · 약 5분

    EC2 콘솔 → 인스턴스 시작.

    이름
    plers-api
    AMI
    Ubuntu Server 24.04 LTS (프리티어 사용 가능 표시 확인)
    아키텍처
    64비트 x86
    인스턴스 유형
    t3.micro
    키 페어
    새 키 페어 생성 → 이름 plers-key · 유형 RSA · 형식 .pem
    방화벽
    기존 보안 그룹 선택 → plers-app-sg
    스토리지
    8GB gp3 (기본값)
    키 파일은 한 번만 받을 수 있습니다

    plers-key.pem이 다운로드 폴더에 저장됩니다. 이 파일이 서버에 들어가는 유일한 열쇠이고 재발급이 안 됩니다. 잃어버리면 서버를 새로 만들어야 하니 안전한 곳에 보관하세요.

    인스턴스가 만들어지면 IP가 재부팅 때마다 바뀌지 않도록 고정 IP를 붙입니다. 왼쪽 메뉴 네트워크 및 보안 → 탄력적 IP → 탄력적 IP 주소 할당 → 만들어진 주소를 선택하고 작업 → 탄력적 IP 주소 연결 → 인스턴스 plers-api 선택.

    인스턴스 상태가 실행 중이고, 탄력적 IP 주소를 메모장에 적어뒀다면 완료. 이 주소가 앞으로 서버의 집주소입니다.

  4. 4

    서버에 접속하기

    내 맥 터미널 · 약 3분

    내려받은 키 파일을 안전한 위치로 옮기고 권한을 잠급니다. 권한이 열려 있으면 SSH가 접속을 거부합니다.

    내 맥 터미널
    # 키 파일을 홈의 .ssh 폴더로 옮기고 권한 잠그기
mkdir -p ~/.ssh
mv ~/Downloads/plers-key.pem ~/.ssh/
chmod 400 ~/.ssh/plers-key.pem

    이제 접속합니다. 탄력적IP 자리에 3단계에서 적어둔 주소를 넣으세요.

    내 맥 터미널
    ssh -i ~/.ssh/plers-key.pem ubuntu@탄력적IP

    처음 접속하면 Are you sure you want to continue connecting?이라고 묻습니다. yes를 입력하고 엔터를 누르세요.

    터미널 왼쪽 표시가 ubuntu@ip-172-31-...:~$로 바뀌면 서버 안에 들어온 것입니다. 여기서부터의 명령은 서버 안에서 실행합니다.

  5. 5

    코드 올리기

    내 맥 터미널 · 약 3분

    서버 접속 창은 그대로 두고, 맥에서 터미널 창을 하나 더 엽니다 (⌘+N). 새 창에서 프로젝트 폴더를 통째로 서버에 복사합니다.

    내 맥 터미널 · 새 창
    # 프로젝트 폴더로 이동
cd ~/plers

# 무거운 폴더는 빼고 서버로 복사
rsync -av --exclude '.venv' --exclude '__pycache__' \
  --exclude '.git' --exclude '.env' \
  -e "ssh -i ~/.ssh/plers-key.pem" \
  services/ ubuntu@탄력적IP:/home/ubuntu/services/
    .env를 일부러 뺐습니다

    내 맥의 .env에는 로컬용 값이 들어 있어서, 서버에서는 6단계에서 서버 전용으로 새로 만듭니다. API 키를 실수로 덮어쓰지 않기 위한 조치입니다.

    서버 접속 창으로 돌아가 ls ~/services를 실행했을 때 deploy와 src 폴더가 보이면 완료.

  6. 6

    환경변수 파일 만들기

    서버 안 · 약 3분

    DB 접속 주소와 API 키를 서버에 저장합니다. 서버 접속 창에서 실행하세요.

    서버 안 (ubuntu@…)
    nano ~/services/.env

    빈 편집기가 열리면 아래 두 줄을 붙여넣고, 대괄호 부분을 본인 값으로 바꿉니다.

    .env 내용
    DATABASE_URL=postgresql://plersadmin:[내암호]@[RDS엔드포인트]:5432/plers
OPENAI_API_KEY=[내OpenAI키]

    다 적었으면 Control+O → 엔터(저장) → Control+X(종료)를 누릅니다. 그다음 이 파일을 나만 읽을 수 있게 잠급니다.

    서버 안 (ubuntu@…)
    chmod 600 ~/services/.env
    따옴표를 쓰지 마세요

    이 파일은 systemd가 그대로 읽기 때문에 값에 따옴표를 붙이면 따옴표까지 암호의 일부로 취급됩니다. = 앞뒤에 공백을 넣어도 안 됩니다. 완성된 줄은 이런 모양이어야 합니다 — DATABASE_URL=postgresql://plersadmin:NaengmyeonDb2026@plers-db.abc123.ap-northeast-2.rds.amazonaws.com:5432/plers

    cat ~/services/.env로 두 줄이 제대로 보이고, 대괄호가 하나도 남아 있지 않으면 완료.

    설치 스크립트 실행

    서버 안 · 약 5분 (자동)

    파이썬 설치, 패키지 설치, 서비스 등록, nginx 설정, DB 테이블 생성까지 한 번에 처리합니다. 2단계의 RDS 상태가 사용 가능이 된 뒤에 실행하세요.

    서버 안 (ubuntu@…)
    bash ~/services/deploy/setup_ec2.sh

    화면에 ==> 1/5부터 ==> 5/5까지 순서대로 지나가고, 마지막에 restaurant_recommendation_profiles 테이블 준비 완료가 나오면 성공입니다. 중간에 빨간 글씨로 멈추면 그 메시지를 그대로 두고 아래 문제 해결 표를 보세요.

    sudo systemctl status plers-api를 실행했을 때 초록색 active (running)이 보이면 완료. 빠져나올 때는 q를 누릅니다.

  8. 8

    동작 확인

    브라우저 · 약 2분

    먼저 서버 안에서 앱이 살아 있는지 확인합니다.

    서버 안 (ubuntu@…)
    curl -i http://127.0.0.1:8000/docs

    첫 줄에 HTTP/1.1 200 OK가 나오면 앱은 정상입니다. 이제 브라우저를 열고 주소창에 아래를 입력하세요.

    브라우저 주소창
    http://탄력적IP/docs

    FastAPI 자동 문서 화면이 뜨고 /api/v1/… 엔드포인트 목록이 보이면 배포 완료입니다. 아무 엔드포인트나 펼쳐 Try it out → Execute를 눌러 실제 응답까지 확인해 보세요.

1 · 내 맥 터미널
cd ~/plers

  -e "ssh -i ~/.ssh/plers-key.pem" \

2 · 서버 안
sudo systemctl restart plers-api
sudo systemctl status plers-api --no-pager

자주 쓰는 확인 명령입니다.

서버 안 · 로그와 상태
# 실시간 로그 보기 (Control+C로 빠져나옴)
sudo journalctl -u plers-api -f

# 최근 오류 50줄
sudo journalctl -u plers-api -n 50 --no-pager

# nginx 설정 검사 후 재시작

SSH 접속이 응답 없이 멈춤 보안 그룹의 SSH 소스가 내 IP인데 인터넷 IP가 바뀐 경우입니다. 카페·회사 등 네트워크를 옮기면 자주 발생합니다. plers-app-sg 인바운드 규칙을 편집해 소스를 내 IP로 다시 저장하세요.
Permissions 0644 for 'plers-key.pem' are too open 키 파일 권한이 열려 있습니다. chmod 400 ~/.ssh/plers-key.pem을 실행하세요.
connection to server … failed: timeout expired EC2가 RDS에 닿지 못하는 상태입니다. RDS의 보안 그룹이 plers-db-sg인지, 그 인바운드 소스가 plers-app-sg인지 확인하세요. RDS에 default 보안 그룹이 남아 있다면 제거합니다.
database "plers" does not exist RDS를 만들 때 초기 데이터베이스 이름을 비워둔 경우입니다. 서버에서 psql "postgresql://plersadmin:암호@엔드포인트:5432/postgres" -c "CREATE DATABASE plers;"로 직접 만들 수 있습니다. psql이 없다면 sudo apt install -y postgresql-client를 먼저 실행하세요.
password authentication failed .env의 암호가 틀렸거나, 암호에 @ : / 같은 기호가 들어가 주소가 잘못 잘린 경우입니다. RDS 콘솔에서 수정 → 새 마스터 암호로 영문+숫자 암호로 바꾸고 .env도 함께 고치세요.
브라우저에서 사이트에 연결할 수 없음 서버 안에서 curl -i http://127.0.0.1:8000/docs가 200이면 앱은 정상이므로 통로 문제입니다. plers-app-sg에 HTTP 80 · Anywhere-IPv4 규칙이 있는지, sudo systemctl status nginx가 running인지 확인하세요. 주소에 https://가 아니라 http://를 썼는지도 확인합니다.
502 Bad Gateway nginx는 살아 있지만 뒤의 앱이 죽은 상태입니다. sudo journalctl -u plers-api -n 50 --no-pager로 파이썬 오류 메시지를 확인하세요. 대부분 .env 오타이거나 DB 연결 실패입니다.
ModuleNotFoundError: No module named 'api' 실행 위치가 잘못된 경우입니다. 이 앱은 src/app이 실행 루트여야 합니다. /etc/systemd/system/plers-api.service의 WorkingDirectory가 /home/ubuntu/services/src/app인지 확인하고, 고쳤다면 sudo systemctl daemon-reload && sudo systemctl restart plers-api를 실행하세요.
재부팅 후 IP가 바뀜 탄력적 IP를 연결하지 않은 경우입니다. 3단계 마지막 항목을 수행하세요.

탄력적 IP를 할당해 두고 어떤 인스턴스에도 연결하지 않으면 시간당 요금이 붙습니다. 서버를 지울 때는 탄력적 IP도 릴리스해야 합니다.

프리티어 조건은 계정 가입 시점에 따라 다릅니다. AWS 콘솔 Billing → 예산에서 월 $5짜리 예산 알림을 만들어두면 예상 밖 요금을 바로 알 수 있습니다.

여기까지 끝낸 다음

당장 필요하진 않지만, 서비스를 실제로 공개할 때 챙겨야 할 것들입니다.

  • HTTPS 붙이기 — 도메인을 준비한 뒤 서버에서 sudo apt install -y certbot python3-certbot-nginx → sudo certbot --nginx를 실행하면 무료 인증서가 자동 설치됩니다. 브라우저 주소가 https://로 바뀝니다.
  • CORS 설정 조이기 — 현재 src/app/main.py는 allow_origins=["*"]와 allow_credentials=True를 함께 쓰고 있습니다. 이 조합은 브라우저가 무시하기 때문에, 프론트엔드를 붙이면 쿠키·인증 요청이 실패합니다. 프론트 주소가 정해지면 allow_origins에 그 주소만 명시하세요.
  • DB 접속 방식 — 지금은 요청마다 새로 연결합니다. 트래픽이 늘면 커넥션 풀 도입을 고려하세요.
  • 암호 보관 — .env 대신 AWS Secrets Manager로 옮기면 서버에 평문 암호를 두지 않아도 됩니다.
